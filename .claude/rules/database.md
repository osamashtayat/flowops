# Database rules (EF Core + PostgreSQL)

Read with: `docs/DOMAIN_MODEL.md` §6, ADR-0006, ADR-0007.

## Boundaries
- Only Application services touch `IAppDbContext`. Controllers and the domain never do.
- No generic repositories. Command services load aggregates; query services project.
- `SaveChangesAsync` exactly once per use case, in the use-case service. No explicit transactions unless a use case truly needs two round trips (none in Phase 1 — flag if you think you need one).

## Queries
- Read paths: `AsNoTracking()` + `Select(...)` to DTOs. Never load entity graphs and map in memory for lists.
- No client-side evaluation; if EF can't translate it, rewrite it.
- Avoid N+1: no queries inside loops; use projections/joins.
- Always page lists (`pageSize` ≤ 100). Order deterministically (add `Id` as tiebreaker).
- Visibility filtering only via `AccessRules.VisibleTo`.

## Schema & migrations
- Entity configuration in `IEntityTypeConfiguration<T>` classes in Infrastructure; no data annotations on domain types.
- snake_case names; enums stored as text with check constraints; money `numeric(18,3)` + `char(3)`; timestamps `timestamptz`; dates `date`.
- Every FK has an index; add the indexes listed in DOMAIN_MODEL.md §6; justify any other new index by a query.
- Constraints encode invariants the DB can know: unique, FKs, `num_nonnulls` checks, `ux_work_tasks_open_per_request`.
- Migrations: one per task, descriptive name (`AddWorkTasks`), generated by `dotnet ef migrations add`, reviewed by reading the generated SQL (`dotnet ef migrations script`). Never edit an applied migration; add a new one.
- Never use `EnsureCreated` outside tests' throwaway databases (and prefer migrations there too).

## Concurrency
- `Request` and `WorkTask` use `xmin` as concurrency token (`IsRowVersion()` on a `uint` property mapped to `xmin`).
- Decisions compare the client `version` before acting and rely on the token at save time. Map conflicts to 409; never retry silently.
- No `FOR UPDATE`, advisory locks or distributed locks without an ADR.

## Data safety
- Seed data for development only behind an explicit flag; never in Production.
- Activities and decision fields are immutable once written.
