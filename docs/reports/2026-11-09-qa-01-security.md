## Notes on open issues
- **#48:** an admin can also reach the same result by resetting an existing second admin's password. ADR-0012 already accepts this; ADR-0013 lists it as residual.
- **#43:** comment bodies also appear in dashboard `recentActivity[].body`, so masking must cover that too.
- **#50, #56, #58, #69:** severity unchanged.

## Checked, no issues
- **Access rules and decisions:** visibility goes only through `AccessRules`, eligibility only through `TaskEligibility`, and the access context is built from the database. 404 vs 403 is used correctly. Versions are checked, and conflicts return 409 without retry.
- **Leave reason:** masked in details, lists, activity, dashboard and notifications.
- **Cookies and CSRF:** cookie flags are correct; unauthenticated calls get 401, not a redirect; there is a global antiforgery filter.
- **Role changes:** checks run against the database; there is no self-approval; the stale, deactivated-proposer and add-Administrator re-checks run.
- **Hub:** `[Authorize]`, no client methods, a 1 KB message limit, a per-user cap.
- **Seeder:** Development only.
- **Docker:** the API publishes no port; nginx overwrites the forwarded headers.
- **CI:** `contents: read`, `pull_request` (not `pull_request_target`).
- **Secrets:** none in committed files.
